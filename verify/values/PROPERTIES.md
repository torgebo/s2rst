# Property Catalogue: the value types (specs 004–007, FR-006)

Sections 1–3 are spec 004's (`Cell`, `s1::Interval`, the generic laws); sections 4–5 are
spec 005's (`r1::Interval` against `verify/src/real_spec.rs`, `s2::Rect` against
`verify/src/rect_spec.rs`; field definitions in
`specs/005-formal-verify-r1-interval-rect/data-model.md` §4); sections 6–7 are spec 006's
(`r2::Rect` against `verify/src/uv_spec.rs`, `s2::Point` against `verify/src/point_spec.rs`;
`specs/006-formal-verify-r2-rect-point/data-model.md` §4), and its generic order laws join
section 3; sections 8–9 are spec 007's (`s1::ChordAngle` against `verify/src/chord_spec.rs`,
`s1::Angle` against `verify/src/angle_spec.rs`; `specs/007-formal-verify-chord-angle-angle/
data-model.md` §4). Spec 007 adds a status, `proven-by-enumeration`: the property's domain is
one `i32`, and a named release-mode test checks every value of it
(`verify/tests/angle_enumeration.rs`; spec 007 FR-008). Section 10 is spec 008's (`s2::Cap`
against `verify/src/cap_spec.rs`; `specs/008-formal-verify-cap/data-model.md` §4), which adds
two statuses: `proven-by-composition` (the harness replaces a recomputed library function by a
lemma stub, a pure function returning any value its lemmas allow, each lemma proven on the real
code; the row names the stubs and lemmas, spec 008 FR-003a) and `proven-under-contract` (the
harness replaces `asin`, `atan2` or `cos` by its range contract, tested against the real
function; the row names the contracts, spec 008 FR-003). Section 11 is spec 010's (`s2::LatLng` against
`verify/src/latlng_spec.rs`; `specs/010-formal-verify-latlng/data-model.md` §4), which also adds
`Rect`'s `Region` law instances to section 5. Its `proven-by-composition` entries also rest on
drift guards, which check that a library formula is its restatement's text where a second copy
of the formula's float products times out in the checker (the row names the guard).

In plain language and grouped by kind of guarantee, with the other catalogues:
[`PROPERTIES_BY_KIND.md`](../PROPERTIES_BY_KIND.md).

The functional properties of the two value types, each stated against an independent
reference description: `verify/src/cell_spec.rs` (a cell is its identifier's decomposition in
001's model, with upstream's u-v projection) and `verify/src/arc_spec.rs` (an interval is the
set of points it denotes). Both are written from upstream C++ at `v0.14.0-40` and checked
against the C++ vectors by `verify/tests/values_spec_vs_cpp.rs`. Field definitions:
`specs/004-formal-verify-cell-interval/data-model.md` §4.

every value of an integer domain, by a native test) | `proven-by-composition` (spec 008: with
