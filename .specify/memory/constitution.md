# s2rst Constitution

## Core Principles

### I. Upstream Parity (NON-NEGOTIABLE)

s2rst is a port of Google's S2 Geometry library. Its value comes from producing the same
answers as upstream.

- Ported algorithms MUST match the semantics of the upstream implementations. C++
  (`google/s2geometry`) is the canonical reference. Go (`golang/geo`) and Java
  (`google/s2-geometry-library-java`) are secondary references.
- A deliberate behavioural deviation from upstream (a different result, a different
  error, or an omitted mode) MUST be documented in the rustdoc of the affected item,
  with the reason.
- Where an independent oracle exists, correctness MUST be checked against it with
  differential tests (`core/tests/*_diff.rs`, `*_cross_validation.rs`), using the
  committed reference vectors generated by `tools/refgen` (Go) and `tools/refgen-cpp`
  (C++). The committed CSVs are the durable artifact, so CI MUST NOT need a Go or C++
  toolchain.
- When correctness and parity conflict with speed or API convenience, correctness and
  parity win.

**Rationale**: The project is beta and its only claim to trust is fidelity to a
well-tested upstream. Same-implementation unit tests cannot catch a flipped predicate
or a drifted result. An independent oracle can.

### II. Robustness & Memory Safety

- The core crate MUST stay free of `unsafe` code (`unsafe_code = "forbid"`). This lint
  MUST NOT be relaxed.
- Geometric predicates MUST give topologically correct results. They use conservative
  floating-point error bounds with exact-arithmetic fallback (`ExactFloat`,
  `PreciseVector`, `num-bigint`). Replacing an exact fallback with an approximation is
  forbidden.
- Decoders and any other API that takes untrusted bytes MUST return a `Result`. They
  MUST NOT panic, abort, or hang on arbitrary input. Each such decoder MUST have
  bounded robustness coverage in `core/tests/decoder_robustness.rs` and a `cargo-fuzz`
  target under `fuzz/fuzz_targets/`.
- A public function that can panic MUST document when it panics (`# Panics`). A public
  function that returns an error MUST document its errors (`# Errors`).

**Rationale**: Downstream users feed S2 with geometry and serialized data they do not
control. Memory safety and panic-freedom on hostile input are properties Rust can
guarantee, and giving them up would remove the main reason to use a Rust port.

### III. Test-Backed Changes

- Every behaviour change and every bug fix MUST come with tests that exercise it. A
  bug-fix test MUST fail without the fix.
- New Rust unit tests for a module MUST go in a sibling `<module>_tests.rs` file, wired
  in with `#[cfg(test)] #[path = "..."] mod ...;`. Existing inline test modules may stay
  as they are.
- Cross-module and integration tests live under `core/tests/`. Algebraic and invariant
  properties (including the trait invariants in `CORE_TRAITS.md`) MUST be expressed as
  `quickcheck` property tests where practical.
- Python behaviour is tested with `pytest` (`python/tests/`), and wasm behaviour with
  `wasm-bindgen` tests under `wasm-pack test --node`.

**Rationale**: The bar for change is correctness and parity with upstream, "kept honest
by the test suite". Untested behaviour is unverified behaviour.

### IV. Thin, Synchronized Bindings

- The Python (`python/`, PyO3) and WebAssembly (`wasm/`) crates MUST be thin wrappers
  over `s2rst`. Geometry algorithms MUST live in `core/` and MUST NOT be reimplemented
  in a binding.
- The Python package is typed. The hand-written stub `python/python/s2rst/_core.pyi`
  MUST match the runtime module, as enforced by `mypy.stubtest` against
  `python/stubtest-allowlist.txt`. Any change to the bindings' public API MUST update
  the stub in the same change.
- Bindings SHOULD turn invalid input into language-native errors (Python exceptions,
  JS errors) instead of relying on core panics.
- All workspace crates share one version (`shared-version = true`) and are released
  together.

**Rationale**: One implementation keeps the three surfaces consistent. Each extra copy
of an algorithm is another place where parity (Principle I) can silently break.

### V. Measured Performance

- A change made for performance MUST be backed by benchmark evidence from the existing
  harnesses. `iai-callgrind` instruction counts are the deterministic regression gate.
  Criterion `wall_*` benches cover effects that instruction counts cannot see (ILP,
  FMA, SIMD).
- Baselines MUST be recorded with `make baseline`, never with `target-cpu=native`
  (`make bench-native` is for tuning experiments only).
- A performance change MUST NOT weaken Principles I or II. A faster predicate that can
  return a topologically wrong answer is a regression.
- Benchmarks are not part of `make test` and MUST NOT be run as part of an ordinary
  change.

**Rationale**: Performance claims without deterministic measurement cannot be reviewed.
Keeping benchmarks out of the default gate keeps routine verification fast.

## Technical Constraints

- **Toolchain**: Rust stable (`rust-toolchain.toml`), edition 2024, workspace MSRV 1.88.
  The MSRV is checked by the CI `msrv` job (`cargo +1.88 check`). Raising the MSRV is a
  deliberate, documented change.
- **Lints**: The `[lints.rust]` and `[lints.clippy]` configuration in `core/Cargo.toml`
  (clippy pedantic, `correctness` denied) is authoritative. A lint that does not fit
  SHOULD be adjusted in the shared config, not through scattered `#[allow]`s. Every
  `#[allow]` MUST carry a `reason = "..."`.
- **Allocation**: When a collection's final size is known up front from trusted data, it
  MUST be allocated once at that size (`Vec::with_capacity`, a fixed-size array) instead
  of growing. A size read from untrusted input MUST NOT drive a reservation (Principle
  II); such collections grow on demand.
- **Documentation**: Public items MUST be documented (`missing_docs`). `make doc` MUST
  build with warnings denied.
- **Dependencies**: The core crate keeps a minimal runtime dependency set. A new
  non-optional runtime dependency MUST be justified in the change description.
  Integrations such as `serde` and `geo-types` MUST be optional features. All
  dependencies MUST pass `cargo-deny` (license allowlist, advisories). Any advisory
  exception needs a written reason in `deny.toml`.
- **Licensing**: The project is Apache-2.0, matching upstream. Every source file MUST
  carry an SPDX header. Ported or derivative files carry the upstream attribution note.
  Original test files (`*_tests.rs`, `core/tests/`) carry only the two-line SPDX header
  and a note that they are original. They MUST NOT carry Google attribution.
- **Maturity**: The software is `0.x` beta and not intended for production. Only the
  latest release and `master` receive fixes. Security issues are handled privately as
  described in `SECURITY.md`.

## Development Workflow & Quality Gates

- **The gate**: `make test` at the workspace root MUST pass before a pull request is
  ready for review. It runs, in order: `check`, `fmt-check`, `clippy` (warnings as
  errors), `test-core`, `doc` (warnings as errors), the Python suite (ruff, mypy +
  stubtest, pytest), the wasm suite, and `cargo-deny`. The CI `test` workflow MUST call
  the same Makefile targets so that local and CI results do not drift.
- **Branching**: Work happens on feature branches off `master`. Non-trivial work SHOULD
  start with an issue, to agree on the approach first.
- **Pull requests**: Each PR MUST satisfy the checklist in
  `.github/PULL_REQUEST_TEMPLATE.md`: gate passes, tests added or updated, docs and
  Python stub updated for public API changes, and no new clippy warnings. PRs SHOULD
  stay focused on one concern.
- **Deep verification**: Nightly `cargo-fuzz` campaigns (`.github/workflows/fuzz.yml`)
  run every fuzz target. A new fuzz target MUST be added to that matrix. Crashes found
  by fuzzing MUST be fixed with a regression test (Principle III).
- **Verification records**: A change that touches `verify/` MUST update, in the same
  change, the records it affects: the suite's operation inventory (`INVENTORY.md`) and
  property catalogue (`PROPERTIES.md`), the properties by kind
  (`verify/PROPERTIES_BY_KIND.md` and the rendered `.html` copies of the catalogues), and
  the inventory of verified types (`VERIFIED_TYPES.md`). A harness, property or type whose
  record is missing or out of date is a defect.
- **Spec Kit plans**: Each `plan.md` MUST fill in its "Constitution Check" against
  Principles I–V. Any violation MUST be justified in "Complexity Tracking" or the plan
  MUST be revised.

## Governance

- This constitution overrides any conflicting development practice. `CONTRIBUTING.md`
  holds the day-to-day contributor guidance, and it MUST NOT contradict this document.
  If the two disagree, fix one of them in the same change.
- **Amendments**: Changes are made by pull request to `.specify/memory/constitution.md`
  (usually through `/speckit-constitution`). The PR states the version bump and its
  rationale, and updates any dependent guidance (`CONTRIBUTING.md`, the PR template,
  Makefile targets) that the amendment affects.
- **Versioning**: The constitution uses semantic versioning. MAJOR: removing or
  redefining a principle in a backward-incompatible way. MINOR: adding a principle or
  section, or materially expanding guidance. PATCH: clarifications and wording fixes
  that do not change meaning.
- **Compliance**: Reviewers check PRs against these principles. A justified exception
  MUST be recorded in the PR description (or in the plan's Complexity Tracking) with
  the reason and the simpler alternative that was rejected. Unrecorded exceptions are
  defects.
