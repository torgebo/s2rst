# PLAN_LACKING — closing the gaps vs. C++ s2geometry

Execution plan for the findings in [LACKING.md](LACKING.md) (IDs H1–H4, M1–M9, and the
low-severity batch refer to that document). Reference implementation:
`~/sources/s2geometry` @ `8d5c2a87`.

## Guiding constraints

- **No unsafe code** — `core/Cargo.toml` sets `unsafe_code = "forbid"`. Lazy decoding
  and interior mutability must use safe primitives (`OnceLock`, `RwLock`, lifetimes
  over `&[u8]`), never raw pointers into buffers.
- **Every ported feature lands with its C++ tests ported** alongside, mirroring the
  existing convention (in-file `#[cfg(test)]` mirroring C++ test names, plus
  `core/tests/` integration suites and `fuzz/fuzz_targets/` for anything that parses
  bytes).
- **Wire-format compatibility is non-negotiable** — new encoders/decoders are
  validated against C++-generated bytes (extend the `core/tests/data/` vectors via
  generators under `tools/refgen-cpp/`; see verification strategy item 2).
- **Pre-1.0 (v0.3.x)**: breaking API changes are acceptable when a phase needs them
  (notably Phase 2's query-signature generalization), but each phase should leave the
  crate releasable.
- Sizes: **S** = hours, **M** = days, **L** = a week-plus of focused work.
- **Out of scope**: `python/`/`wasm/` binding parity (re-plan once the core APIs from
  Phases 2–4 settle), performance parity beyond the stated benchmark gates, and
  C++ test-only infrastructure (gmock matchers, flag-based seeding).

## Phase overview and ordering rationale

| Phase | Theme | Items | Why this order |
|-------|-------|-------|----------------|
| 0 | Correctness | H1 | Wrong answers outrank missing features. |
| 1 | Quick functional wins | H2, M8, M4, M5, M2, M3 | Small, independent, user-visible; no architectural prerequisites. |
| 2 | Index/iterator abstraction | M1 (+ index trait) | Prerequisite for Phase 3; unlocks generic joins now. |
| 3 | Lazy encoded family | H3 | The big scalability gap; builds directly on Phase 2. |
| 4 | Dynamic ShapeIndex | H4 | Independent of Phase 3 but touches the same file; staged to avoid conflicts. |
| 5 | Encoding control | M6 | Pure API surface; cheap once Phase 3 settles formats. |
| 6 | Predicate fast path | M7 | Speculative perf; benchmark-gated, do last. |
| 7 | Low-severity batch | L1–L13 | Sweep of conveniences; fill idle time between phases. |

Phases 2→3 are strictly sequential. Phases 0, 1 and 7 can interleave with anything.
Phase 4 should not run concurrently with Phase 3 (both rework `shape_index.rs`).

## Phase 0 — Correctness: boolean operation degeneracies (H1) — **M**

**Goal.** Un-ignore the three ported regression tests
(`core/src/s2/boolean_operation/mod.rs:3459`, `:3515`, `:3855`,
"GetCrossedVertexIndex edge case not yet handled").

**Approach.**
1. Diff the Rust `get_crossed_vertex_index` in
   `core/src/s2/boolean_operation/graph_edge_clipper.rs` against C++
   `GraphEdgeClipper::GetCrossedVertexIndex` in `s2boolean_operation.cc`, which
   contains the upstream fixes for bugs 1, 2 and 6 (vertex-ordering fallback logic
   when input edges cross at nearly-identical vertices).
2. Port the missing fallback branch(es); keep the C++ comments explaining the
   invariants — this code is subtle.
3. Re-enable the three tests; run the full boolean-operation suite plus
   `core/tests/polygon_operations.rs` and the `boolean_operation` bench to catch
   regressions.

**Done when** all three `#[ignore]` attributes are removed and the suite is green.
**Risk.** The C++ fix may depend on `GetVoronoiSiteExclusion`/predicate behavior in
edge cases — if a test still fails after a faithful port, instrument both sides on
the failing input before changing predicate code.

**Outcome (2026-06-10, `0ebc4cc`) — done.** The risk note was prophetic: the
clipper port already matched post-fix upstream. Instrumented traces on both
implementations showed identical snapped graphs but one crossing with an
inverted `left_to_right`; a minimal repro plus an exact rational determinant
(−3.55e-27) proved the Rust `Sign` wrong. Root cause: `predicates::sign` is the
port of non-robust `S2::SimpleCCW`, but `init_index_crossings` (and
`Polyline::is_on_right`) used it where C++ calls the robust `s2pred::Sign`.
Fixed both call sites, renamed `sign` → `simple_ccw` to kill the naming trap,
un-ignored the three tests; full suite 3422/0. No bench run needed: the changed
paths run once per crossing pair / `is_on_right` call, and `robust_sign`'s
triage tier costs the same as the simple test on non-degenerate input.
Follow-up discovered and filed as L14: `edge_distances::project` still ports
the older C++ formulation.

## Phase 2 — Cell-iterator and index abstraction (M1) — **L**

The architectural keystone: both the generic join (M1) and the lazy encoded index
(H3) need queries and join algorithms to stop depending on the concrete
`ShapeIndex`. Today every query holds `&'a ShapeIndex`
(`edge_query.rs:281`, `contains_point_query.rs:71`, `crossing_edge_query.rs:54`, …).

**Steps.**
1. **Define traits** in a new `core/src/s2/cell_iterator.rs`, mirroring
   `s2cell_iterator.h`:
   - `trait CellIterator { fn id(&self) -> CellId; fn done(&self) -> bool; fn begin/finish/next/prev/seek(...); fn locate_point(...); fn locate_cell_id(...) -> CellRelation; }`
   - a generic `CellRangeIterator<I: CellIterator>` (port of
     `s2cell_range_iterator.h`) replacing the ShapeIndex-specific
     `cell_range_iterator.rs`.
2. **Define an index trait** (working name `ShapeIndexLike`), the analogue of the
   abstract C++ `S2ShapeIndex` base: `num_shape_ids()`, `shape(id) -> Option<&dyn
   Shape>`, an associated iterator type implementing `CellIterator` whose item also
   exposes the cell contents (`&ShapeIndexCell`). Implement it for `ShapeIndex`.
   *Design note:* the iterator borrows the index, so this is a generic associated
   type (`type Iter<'a>: CellIterator where Self: 'a`) — supported on MSRV 1.88.
   Spike this trait signature against ONE query before converting the rest; it
   shapes every subsequent conversion and is the cheapest place to discover a dead
   end.
   *Spike outcome (2026-06-10, `2b7fe71`) — design validated.* `CellIterator`
   (default `locate_*` impls porting `LocateImpl`) + `ShapeIndexLike` with
   `type Iter<'a>: CellIterator + IndexCellAccess<'a>`; `ContainsPointQuery`
   converted with `ShapeIndex` as default type parameter — zero call-site
   changes except an explicit reborrow (`&*guard`) where wasm passes RefCell
   guards (deref coercion doesn't fire for generic params; expect the same in
   the remaining conversions). Two recorded decisions: (1) cell contents are
   returned at the *index* lifetime, so the Phase 3 lazy index must cache
   decoded cells inside the index (per-cell `OnceLock`), not decode per
   access; (2) no blanket impl for smart pointers (coherence), callers
   reborrow. iai bench: 0 regressions.
3. **Generalize consumers incrementally**: convert queries one at a time to
   `Query<'a, I: ShapeIndexLike>` with a default so existing call sites keep working
   (type alias `ClosestEdgeQuery<'a> = GenericClosestEdgeQuery<'a, ShapeIndex>`).
   Start with `contains_point_query` (smallest), end with `edge_query` (largest).
4. **Generalize the join**: `S2CellIteratorJoin<A: CellIterator, B: CellIterator>`
   (`cell_iterator_join.rs:32` currently hardcodes two `&ShapeIndex`), with the
   tolerance variant preserved. Implement `CellIterator` for: `ShapeIndexIterator`,
   `CellIndexRangeIterator`-backed adapter, a new `CellUnion` iterator, and
   `S2PointIndex`'s map iterator.
   *Done 2026-06-10 (`226f470`) with one amendment: no `CellIndex` adapter —
   nested cells violate the disjointness contract (upstream C++ agrees: its
   `S2CellIndex` iterators don't implement `S2CellIterator`).*
5. Port `s2cell_iterator_join_test.cc` cases that join heterogeneous containers.
   *Covered by the CellUnion×ShapeIndex (brute-force-verified) and
   PointIndex×CellUnion tests in `cell_iterator_join.rs`.*

**Done when** a `CellIndex` can be joined against a `ShapeIndex`, and at least one
query type is generic over the index trait with no measurable benchmark regression
(`cargo bench --bench shape_index`, `closest_edge_query`) — monomorphization should
make this free, but verify.

**Risk.** Trait-object vs. generic tension: keep queries generic (static dispatch);
avoid `dyn ShapeIndexLike` in hot paths. Watch compile-time/code-size growth.

## Phase 3 — Lazy encoded family (H3) — **L** (depends on Phase 2)

Recover the C++ design point: serve queries from encoded bytes with ~O(1) init.
Work bottom-up; each step is independently releasable.

1. **Lazy primitive vectors** — **M**. Add view structs over `&'a [u8]`:
   `EncodedUintVector<'a, T>` (with `len`, `get(i)`, `lower_bound`),
   `EncodedS2CellIdVector<'a>` (delta/base form, `lower_bound`),
   `EncodedStringVector<'a>`, `EncodedS2PointVector<'a>` (both UNCOMPRESSED and
   CELL_IDS forms). Keep the existing eager `decode_*` functions as conveniences
   delegating to the views. Extend the existing fuzz targets
   (`fuzz/fuzz_targets/decode_*.rs`) to exercise random access through the views,
   not just full decode; malformed input must error, never panic.
2. **Lazy lax shapes** — **M**. `EncodedLaxPolygonShape<'a>` /
   `EncodedLaxPolylineShape<'a>` over the lazy vectors, implementing `Shape`
   (port `s2lax_polygon_shape.h:196`, `s2lax_polyline_shape.h:110`). Requires `Shape`
   to be implementable by borrowing types — check for `'static` bounds on
   `Box<dyn Shape>` usage and relax where needed (or provide owning variants holding
   `Vec<u8>`/`Bytes`-style buffers; **decision point**: borrowed `&'a [u8]` vs owned
   `Arc<[u8]>` — owned avoids lifetime plumbing through indexes and is the
   recommended default, with borrowing as a later optimization).
3. **`ShapeFactory` abstraction** — **S/M**. Port `s2shape_index.h:504`: a trait
   producing shapes by id from encoded bytes; provide `TaggedShapeFactory`
   (the 5 type tags in `shape_index_encoding.rs:68-126`) and
   `HomogeneousShapeFactory` equivalents.
4. **True lazy `EncodedS2ShapeIndex`** — **L**. Reimplement
   `core/src/s2/encoded_s2shape_index.rs` as a real index over `Arc<[u8]>`:
   - cell-id vector + cell-offsets via the lazy vectors; decode an
     `ShapeIndexCell` per access (no cache initially — contents are small and C++'s
     own iterator decodes per position);
   - shape table as `Vec<OnceLock<Box<dyn Shape>>>` for thread-safe one-time decode
     (safe-code substitute for C++ atomics);
   - implement the Phase-2 `ShapeIndexLike` trait so every generic query runs on it
     unchanged.
5. **Validation & benches.** Cross-validate against C++-encoded indexes (extend
   `cpp_cross_validation` vectors with an encoded-index section); add a criterion
   bench comparing init+single-query latency of eager vs lazy on a large index —
   the lazy path should be orders of magnitude faster on init; keep
   `decode_s2shape_index` fuzz target pointed at the lazy path.

**Done when** `EncodedS2ShapeIndex::init` no longer materializes shapes/cells up
front, all queries work on it through the trait, fuzzing is clean, and the doc
comment at `encoded_s2shape_index.rs:12-14` describing eager decoding is deleted.

## Phase 4 — Dynamic `ShapeIndex` (H4) — **L** (after Phase 3 merges)

Stage the C++ `MutableS2ShapeIndex` lifecycle; each stage is shippable.

1. **Remove/replace with rebuild semantics** — **M**. Add
   `release(ShapeId) -> Option<Box<dyn Shape>>`, `release_all()`, `clear()`, keeping
   C++ id semantics (ids never reused; `shape(id)` returns `None` for gaps — the
   `add_option` plumbing at `shape_index.rs:392` already anticipates gaps). First
   cut may mark the index stale and rebuild fully on next `build()`.
2. **Lazy build-on-query** — **M**. Introduce interior mutability so queries on a
   stale index trigger a build: pending-updates list + `RwLock`-guarded cell map (or
   `OnceLock` around an immutable snapshot). Preserve `Send + Sync`
   (`core/tests/send_sync.rs` must keep passing) and benchmark read-path overhead —
   an acceptable design is C++-like: an atomic "fresh" flag checked per iterator
   creation, write lock taken only when stale. Update query docs/examples that
   currently say "call `index.build()` first" (`contains_point_query.rs:62`).
3. **Incremental updates (BatchGenerator port)** — **L, optional**. Port the C++
   batched-update algorithm (apply adds/removes per face without full rebuild) from
   `mutable_s2shape_index.cc`. Justify with a benchmark (mutate 1% of shapes,
   re-query) before committing — full rebuild may be acceptable for this crate's
   users; record the decision here either way.
4. **Options & memory tracking** — **S/M**. Add an `Options` struct
   (`max_edges_per_cell`, future-proofed), `minimize()`, `space_used()` parity, and
   wire `Option<Arc<Mutex<S2MemoryTracker>>>` into index construction like
   builder/buffer/boolean ops already do (`builder/mod.rs:356`).

**Done when** the ported C++ `MutableS2ShapeIndexTest` add/remove/lazy tests pass and
concurrent first-query from multiple threads is exercised by a test.

## Phase 5 — Encoding control & coder framework (M6) — **S/M**

1. Make compact encoders public and hint-driven: `encode_with_hint(w, CodingHint)`
   for `Polyline`, `Polygon`, `Loop` (FAST = lossless, COMPACT = snapped/compressed
   when smaller), promoting `encode_polyline_compressed`
   (`encoding.rs:375`) from `pub(crate)`; `Polygon::encode` keeps auto-selection as
   the `S2Encode` default but documents it.
2. Optional `S2Coder`-style trait (`trait Coder<T> { fn encode(..); fn decode(..); }`)
   with `BasicCoder`/`HintCoder` impls — only if a concrete consumer (e.g. python
   bindings or `CellIndex` serialization) needs polymorphic coders; otherwise record
   as "won't do" with rationale.
3. **Decision point — error type**: keep `io::Error` (status quo) vs introduce
   `S2Error`-carrying decode errors. Recommendation: add a thin
   `DecodeError { kind, context }` wrapping `io::Error` only if Phase 3 fuzzing shows
   diagnostic need; do not churn the whole API for parity alone.
4. Partial/error-tolerant decode overloads for point vectors (LACKING L11) fold in
   here if demand exists; otherwise skip.

**Done when** FAST and COMPACT outputs for `Polyline`/`Polygon`/`Loop` round-trip
against C++-generated bytes in both directions, and decision points (2) and (3) are
resolved and recorded in this file.

## Phase 6 — Intermediate-precision predicate tier (M7) — **M/L, benchmark-gated**

C++ inserts a `long double` tier between f64 triage and exact arithmetic; Rust falls
straight to `ExactFloat`/symbolic (`predicates.rs:197-240`).

1. **Measure first.** Add counters (test-only feature flag) or a micro-bench on
   near-degenerate inputs (`benches/predicates.rs`, `wall/predicates.rs`) to quantify
   how often real workloads (S2Builder snapping, boolean ops on adversarial data) hit
   the exact path, and what it costs end-to-end.
2. If justified: implement a **double-double** tier (TwoSum/TwoProduct, ~106-bit
   mantissa — strictly tighter than C++'s 80-bit `long double`) for the triage
   predicates (`TriageCompareSin2Distances`-family, `stable_sign` analogue), with
   re-derived error constants. This is delicate numerics: every constant must be
   derived in comments like upstream, and results must stay bit-identical to the
   exact path on the full predicate test matrix (`predicates_tests.rs` consistency
   tests across tiers).
3. If not justified by measurements, close M7 as "won't do — measured negligible",
   recording the numbers here.

## Cross-cutting verification strategy

Applied uniformly; phases reference it instead of restating it.

1. **Ported C++ unit tests** land in the same commit as each feature, keeping the
   repo's mirror-the-C++-test-name convention.
2. **Differential vectors**: each phase that touches geometry or bytes extends
   `core/tests/data/cpp_test_vectors.csv` and the `cpp_cross_validation` suite.
   *Verified 2026-06-10:* the C++ reference builds and installs
   (`cmake --install ~/sources/s2geometry/build` → `/tmp/s2-install`, note `/tmp`
   is wiped on reboot — re-install takes seconds), and the repo's generator
   `tools/refgen-cpp/generate_cellid` builds against it and reproduces
   `cpp_cellid_vectors.csv` byte-for-byte (run with
   `LD_LIBRARY_PATH=/tmp/s2-install/lib`; the binary's RUNPATH does not cover
   libs2's transitive abseil deps).
   **Gap found 2026-06-10, closed same day:** the generator for
   `cpp_test_vectors.csv` cited in `core/tests/cpp_cross_validation.rs` existed
   in neither repo. Recreated at the cited path
   (`s2geometry/doc/examples/generate_test_vectors.cc`, plus a CMakeLists
   entry; examples build only with `BUILD_TESTS=ON`, or compile directly per
   the instructions now in `cpp_cross_validation.rs`). The byte-for-byte
   reproduction gate could **not** be met: the original seed/scheme is
   unrecoverable (searched mnemonic seeds, commit-epoch windows, and the full
   32-bit seed space across mt19937_64/mt19937 × four input schemes — no hit;
   a 64-bit literal seed is unsearchable). Decision per R5/R6 policy: the CSV
   was regenerated with a documented seed (0x52715271) and validated instead —
   all 12 cross-validation tests pass against the 60,000 fresh C++-oracle
   vectors. Committed: generator in s2geometry `37a4501`, regenerated CSV +
   provenance comment in s2rst `895242b`. Going forward the generator and CSV
   are committed in lock-step, so this cannot recur.
3. **Fuzzing**: every byte-parsing path, including the Phase 3 lazy random-access
   paths, is covered by a target under `fuzz/fuzz_targets/`; malformed input must
   error, never panic. Run each target locally (≥10 min) before merge.
4. **Benchmark gates**: no >2% regression on `shape_index`, `closest_edge_query`,
   `predicates`, `boolean_operation` benches for refactor phases (2, 4); Phase 3
   must demonstrate ≥100× init speedup on the large encoded-index fixture. Record
   baseline numbers before starting Phases 2–4, not after.
5. **Compile-time guarantees**: `core/tests/send_sync.rs` stays green; new public
   types get added to it. Clippy/lint wall stays clean (`unsafe_code = "forbid"`).

## Critical path and effort rollup

Critical path: **Phase 2 → Phase 3 → Phase 4** (three sequential L items, the only
hard dependency chain): roughly 4–7 focused weeks. Everything else is off-path:
Phase 0 + Phase 1 ≈ 1–2 weeks and can ship as milestone 1 while Phase 2 is spiked;
Phases 5–7 ≈ 1–2 weeks combined, slotted between reviews. Total ≈ 6–10 focused
weeks, excluding Phase 6 (benchmark-gated, possibly zero). Treat these as planning
numbers to be re-validated after the Phase 2 spike — that spike is the single
largest uncertainty reducer in the plan.
